Copy-paste docker-compose stacks that put Bedrud behind **Caddy**, **Traefik**, **nginx** or **HAProxy**. The proxy owns the only public HTTPS port (443, plus 80 for certificates and redirects). Bedrud's own ports stay on a private Docker network.

For CDNs such as Cloudflare, or for an installer-based (non-Docker) setup, see [Behind a Proxy/CDN](/en/docs/guides/behind-proxy).

---

## What goes through the proxy

Bedrud is one binary: the web app, the REST API and the LiveKit signaling endpoint are all served by Bedrud's HTTP listener. Embedded LiveKit listens on `127.0.0.1:7880` inside the container, and Bedrud forwards `/livekit/*` to it. WebRTC media is different: it is UDP (with a TCP fallback) and cannot pass through an HTTP reverse proxy.

| Traffic | Through the proxy on 443? | Port inside the container |
|---------|---------------------------|---------------------------|
| Web app (SPA) | Yes | `8090/tcp` (Bedrud `server.port`) |
| REST API `/api/*` | Yes | `8090/tcp` |
| LiveKit signaling `/livekit/*` (WebSocket) | Yes | `8090/tcp`, then Bedrud → `127.0.0.1:7880` |
| WebRTC media | **No** | `50000-60000/udp` (LiveKit default ICE range) |
| WebRTC TCP fallback | **No** | `7881/tcp` (LiveKit default) |

So a "443 only" deployment is not possible with an HTTP proxy alone. Clients still need the media ports above to reach Bedrud's public IP directly.

<Callout type="warning">
    **TURN is not enabled in this setup.** Embedded LiveKit only turns on TURN (`3478/udp`, TURN/TLS `5349/tcp`) when Bedrud itself serves TLS from certificate files. When TLS ends at the proxy, clients on networks that block both UDP and port 7881 cannot send media. If you need TURN, give LiveKit its own config with `livekit.configPath` (you then own its keys, `node_ip`, ports and webhook) and publish the TURN ports on the `bedrud` service.
</Callout>

## Shared files

Every recipe uses the same `config.yaml` and base `docker-compose.yml`. Put them in one directory with the proxy files from the section you pick.

### config.yaml

Generate each secret with `openssl rand -hex 32`. Replace `meet.example.com` with your domain and `203.0.113.10` with the server's public IP.

```yaml
# config.yaml
server:
  host: "0.0.0.0"
  port: "8090"
  # Embedded LiveKit sends room events to http://localhost:<httpPort>/api/livekit/webhook.
  # With TLS off Bedrud listens on `port`, so httpPort must match it or no webhook is configured.
  httpPort: "8090"
  # TLS ends at the proxy. Leave Bedrud's own TLS and ACME off so only one side owns the certificate.
  enableTLS: false
  behindProxy: true
  # The private compose network. Only containers on it may set the client IP header.
  trustedProxies: ["172.30.0.0/24"]
  proxyHeader: "X-Forwarded-For"

database:
  type: "sqlite"
  path: "/var/lib/bedrud/bedrud.db"

livekit:
  # The URL browsers use for signaling: your public origin plus /livekit.
  host: "https://meet.example.com/livekit"
  # A loopback internalHost keeps LiveKit embedded and served under /livekit.
  internalHost: "http://127.0.0.1:7880"
  apiKey: "bedrud"
  apiSecret: "<generated secret>"
  # The public IP browsers send media to.
  nodeIP: "203.0.113.10"

auth:
  jwtSecret: "<generated secret>"
  sessionSecret: "<generated secret>"
  # Access token lifetime in hours.
  tokenDuration: 24
  frontendURL: "https://meet.example.com"

cors:
  allowedOrigins: "https://meet.example.com"
  allowCredentials: true
```

What each proxy-related key does, and what breaks without it:

| Key | Why it matters | When it is wrong |
|-----|----------------|------------------|
| `server.behindProxy` | Marks auth cookies `Secure` while Bedrud itself speaks plain HTTP, and turns on trusted-proxy mode | Without it, every client shares the proxy's IP for rate limiting |
| `server.trustedProxies` | IPs or CIDRs allowed to set the client IP header | Empty while `behindProxy: true` → Bedrud refuses to start |
| `server.proxyHeader` | Header Bedrud reads the client IP from (default `X-Forwarded-For`) | Bedrud uses the header value as-is, so the proxy must **replace** it with the client address, not append to a client-sent one. Every recipe below does that |
| `livekit.host` | Signaling URL returned by the room join API | Left at `ws://localhost:…` → the web UI loads but joining a room fails |
| `livekit.internalHost` | Must contain `127.0.0.1` or `localhost` to start embedded LiveKit and serve `/livekit` | Any other host is treated as an external LiveKit server |
| `livekit.nodeIP` | IP that LiveKit advertises in ICE candidates | Unset in Docker → Bedrud falls back to the container's own address; rooms join but audio and video never connect |
| `server.httpPort` | Port the embedded LiveKit webhook calls back on | Unset → no webhook, so disconnects are not detected |
| `auth.tokenDuration` | Access token lifetime in hours | Unset → tokens expire as soon as they are issued and every signed-in request fails |

The config file is required: `auth.sessionSecret` and `server.behindProxy` have no environment variable. Other keys can be overridden with the environment variables listed in the [Configuration Reference](/en/docs/getting-started/configuration), for example `SERVER_TRUSTED_PROXIES`, `LIVEKIT_HOST` and `LIVEKIT_NODE_IP`.

### docker-compose.yml

```yaml
# docker-compose.yml
services:
  bedrud:
    image: ghcr.io/themadorg/bedrud:latest
    restart: unless-stopped
    environment:
      CONFIG_PATH: /etc/bedrud/config.yaml
    volumes:
      - ./config.yaml:/etc/bedrud/config.yaml:ro
      - bedrud-data:/var/lib/bedrud
    # 8090 (HTTP) and 7880 (LiveKit) are not published: only the proxy reaches them, over the compose network.
    # WebRTC media cannot pass through an HTTP proxy, so LiveKit's media ports are published directly.
    ports:
      - "7881:7881/tcp"
      - "50000-60000:50000-60000/udp"
    networks: [proxy]

networks:
  proxy:
    ipam:
      config:
        - subnet: 172.30.0.0/24

volumes:
  bedrud-data:
```

Each release also ships the image as an archive (`bedrud-docker-<variant>-<arch>.tar.gz`). If you load one with `docker load -i`, set `image:` to the tag it prints.

Start any recipe with both files:

```bash
docker compose -f docker-compose.yml -f docker-compose.<proxy>.yml up -d
```

## Caddy

Caddy gets a Let's Encrypt certificate on its own, passes WebSockets through, and sets `X-Forwarded-For` to the client address (it ignores a value sent by the client).

```yaml
# docker-compose.caddy.yml
services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
      - caddy-config:/config
    networks: [proxy]
    depends_on: [bedrud]

volumes:
  caddy-data:
  caddy-config:
```

```txt
# Caddyfile
meet.example.com {
	reverse_proxy bedrud:8090
}
```

## Traefik

Traefik reads its routes from labels on the `bedrud` service and gets a certificate through the HTTP-01 challenge on port 80. It passes WebSockets through and replaces client-sent `X-Forwarded-*` headers by default.

```yaml
# docker-compose.traefik.yml
services:
  traefik:
    image: traefik:v3.6
    restart: unless-stopped
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.web.http.redirections.entrypoint.scheme=https
      - --entrypoints.websecure.address=:443
      - --certificatesresolvers.le.acme.email=admin@example.com
      - --certificatesresolvers.le.acme.storage=/letsencrypt/acme.json
      - --certificatesresolvers.le.acme.httpchallenge.entrypoint=web
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - traefik-letsencrypt:/letsencrypt
    networks: [proxy]

  bedrud:
    labels:
      - traefik.enable=true
      - traefik.http.routers.bedrud.rule=Host(`meet.example.com`)
      - traefik.http.routers.bedrud.entrypoints=websecure
      - traefik.http.routers.bedrud.tls.certresolver=le
      - traefik.http.services.bedrud.loadbalancer.server.port=8090

volumes:
  traefik-letsencrypt:
```

## nginx

nginx needs certificate files. This example mounts the Let's Encrypt directory that `certbot` writes on the host. Raise `client_max_body_size` if you raise `chat.uploads.maxBytes` (default 10 MB); nginx's own default of 1 MB would reject chat uploads.

```yaml
# docker-compose.nginx.yml
services:
  nginx:
    image: nginx:1.29
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - /etc/letsencrypt:/etc/letsencrypt:ro
    networks: [proxy]
    depends_on: [bedrud]
```

```nginx
# nginx.conf
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name meet.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name meet.example.com;

    ssl_certificate     /etc/letsencrypt/live/meet.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/meet.example.com/privkey.pem;

    client_max_body_size 10m;

    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header X-Real-IP $remote_addr;
    # Replace, not append: Bedrud reads this header as the client IP.
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;

    location / {
        proxy_pass http://bedrud:8090;
    }

    # LiveKit signaling WebSockets stay open for the whole meeting.
    location /livekit/ {
        proxy_pass http://bedrud:8090;
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
        proxy_buffering off;
    }
}
```

## HAProxy

HAProxy expects the certificate and key concatenated into one PEM file. `timeout tunnel` keeps the LiveKit WebSocket open; without it, HAProxy closes the connection after `timeout server`.

```yaml
# docker-compose.haproxy.yml
services:
  haproxy:
    image: haproxy:3.2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./haproxy.cfg:/usr/local/etc/haproxy/haproxy.cfg:ro
      - ./certs:/usr/local/etc/haproxy/certs:ro
    networks: [proxy]
    depends_on: [bedrud]
```

```txt
# haproxy.cfg
global
    log stdout format raw local0

defaults
    mode http
    log global
    option httplog
    timeout connect 5s
    timeout client 60s
    timeout server 60s
    timeout http-request 10s
    # LiveKit signaling WebSockets stay open for the whole meeting.
    timeout tunnel 1h

frontend public
    bind :80
    bind :443 ssl crt /usr/local/etc/haproxy/certs/meet.example.com.pem alpn h2,http/1.1
    http-request redirect scheme https code 301 unless { ssl_fc }
    # Replace, not append: Bedrud reads this header as the client IP.
    http-request set-header X-Forwarded-For %[src]
    http-request set-header X-Real-IP %[src]
    http-request set-header X-Forwarded-Proto https
    default_backend bedrud

backend bedrud
    option httpchk GET /api/health
    server bedrud bedrud:8090 check
```

## Firewall

| Port | Protocol | Open to | Purpose |
|------|----------|---------|---------|
| 443 | TCP | Public | Web app, API, LiveKit signaling (via the proxy) |
| 80 | TCP | Public | Certificate challenges and redirect to HTTPS |
| 50000-60000 | UDP | Public | WebRTC media |
| 7881 | TCP | Public | WebRTC TCP fallback |
| 8090 | TCP | Not published | Bedrud HTTP, reached only over the compose network |
| 7880 | TCP | Not published | Embedded LiveKit, reached only by Bedrud |

<Callout type="warning">
    Docker publishes ports by writing its own iptables rules, which bypass `ufw`. Keep 8090 and 7880 out of `ports:` instead of relying on the host firewall to hide them.
</Callout>

## Verify

1. Health through the proxy:
   ```bash
   curl https://meet.example.com/api/health
   # {"status":"healthy","time":...}
   ```
2. Bedrud is not reachable directly:
   ```bash
   curl --max-time 3 http://meet.example.com:8090/api/health   # should time out or be refused
   ```
3. Join a room in the browser. In the browser dev tools, the `/api/room/join` response must show `livekitHost` as `https://meet.example.com/livekit`, not a `localhost` or `ws://` URL, and the `/livekit/rtc` request must return `101 Switching Protocols`.
4. If the room joins but nobody sees or hears each other, media is not arriving: check `livekit.nodeIP` and that `50000-60000/udp` and `7881/tcp` are open.

## Using an external LiveKit server

With `livekit.external: true` Bedrud does not start LiveKit and does not serve `/livekit`. Set `livekit.host` to the LiveKit server's own public URL; browsers connect to it directly, so it needs its own TLS and its own media ports. Point that server's webhook at `https://meet.example.com/api/livekit/webhook`. See [Behind a Proxy/CDN](/en/docs/guides/behind-proxy#option-2-external-livekit-server).
